# 我的游戏化作品集

用五个游戏化页面记录你做过的事、正在探索的方向，以及希望别人怎样认识你。适合学生、自由职业者、转行者，也适合只想分享生活和兴趣的人。

## 现在就开始

1. 在你拿到的 GitHub 项目仓库页面点 **Code → Download ZIP**。如果手上已有 ZIP，直接解压。找到解压后同时包含 `README.md` 和 `index.html` 的文件夹。 [GitHub 下载说明](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)
2. 在 Codex、Claude Code、WorkBuddy 等能读写本地文件的 AI 编程工具中打开这个文件夹。如果使用终端版，在这个文件夹中启动工具。
3. 在聊天框发送这句话。

> 我想把这个网站变成自己的个人作品集，但我完全不会编程。你先看看项目里的使用说明，然后一步步引导我完成吧。能帮我直接做的就直接做，需要我提供什么资料就问我。

有简历、作品或链接，可以在聊到相关页面时发给 AI。手头只有一句自我介绍，也可以开始。想提前整理时，可以使用[个人资料模板](个人资料模板.md)。

AI 会从打开的项目文件夹读取使用说明和[制作规则](AGENTS.md)。已有本地进度时先接着做，新项目则从首页开始。

## AI 会怎样带你做

| 顺序 | 页面 | 聊什么 |
| --- | --- | --- |
| 1 | 首页 | 想怎样介绍自己、擅长什么、喜欢什么。初次制作可直接沿用默认动态角色。 |
| 2 | 成就档案库 | 做过的事、自己的贡献和成果。课程、个人尝试和爱好作品都可以展示，素材和数字可留空。 |
| 3 | 支线任务 | 感兴趣的问题、日常观察或喜欢的书影音，选自己愿意分享的话题。 |
| 4 | 灵感实验室 | 想尝试或已经动手做的事，只有一个想法也可以。 |
| 5 | 关于玩家 | 可公开的资料、自己确认的六维属性、人生存档、技能及可选的合作和联系方式。 |

AI 每轮只问一到三个与当前页有关的问题，直接帮你编辑、运行和检查。每页发给你一个本地预览链接，你确认后才继续。可以说「先跳过」「回到首页改一句话」或「下次再继续」。重开同一个文件夹时，发「按上次进度继续做」，AI 会接着未完成的位置。

## 看本地预览

让 AI「启动本地预览并给我链接」。通常可以直接访问 `http://127.0.0.1:8000/`，实际地址以 AI 验证后发给你的为准。改完刷新网页就能看到结果。浏览器地址应是本机网址，避免直接双击 HTML 文件。

如果你自己想启动，打开项目文件夹中的终端，运行 `python -m http.server 8000 --bind 127.0.0.1`。Windows 上也可以用 `py -m http.server 8000 --bind 127.0.0.1`。没有 Python 时，先让 AI 查找已有的本地预览工具。

## 角色怎么选

| 选择 | 要准备什么 | 首页效果 |
| --- | --- | --- |
| A 保留默认动态角色 | 无 | 延续原有睡觉、唤醒、视线跟随和闲置回睡。 |
| B 换成静态角色 | 一张能公开的自己的角色图，可再加一张清醒图 | 点击后显示上线状态，闲置后休息。单图也能用，画面保持静态。 |
| C 定制动态角色 | 先做角色图，再准备绿幕头部转动和所选的睡醒动作视频 | AI 按实际视频适配并测试，验收后切换入口。 |

先把五页内容做完，再决定是否更换角色。不会做视频就选 B，也可以用已有的角色图。需要制作素材时，把[角色素材生成指南](角色素材生成指南.md)交给 AI。

用参考图制作原创手绘角色时，可以让 AI 按官方说明安装 `ian-xiaohei-illustrations`。只有需要整理和接入自定义动态视频时，才需要考虑 `oil-motion`。保留默认角色或使用已有静态图，无需安装这两个 Skill。 [ian-xiaohei 安装说明](https://github.com/helloianneo/ian-xiaohei-illustrations#安装) · [oil-motion 安装说明](https://github.com/oil-oil/oil-motion#安装)

## 发布到自己的 GitHub Pages

1. 五页确认后，让 AI 按[网站验收清单](网站验收清单.md)检查，列出**实际准备上传的文件**。核对所有名字、作品、图片、联系方式和授权。测试通过后，你再确认是否公开。
2. 在自己的 GitHub 账号下创建一个新仓库。常见用法是选择公开仓库，例如 `my-portfolio`。GitHub Free 的 Pages 可用于公开仓库。让 AI 帮你把获准公开的文件提交到你自己的仓库，保持 `index.html`、`assets/` 和 `.nojekyll` 在仓库根目录。 [GitHub Pages 站点说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
3. 在新仓库中打开 **Settings → Pages**，选择 **Deploy from a branch**，选存放站点的分支（通常是 `main`）和 `/(root)`，保存。发布完成后打开 Pages 显示的地址。普通项目网址形式是 `https://你的用户名.github.io/仓库名/`。用这个地址复查五页和图片。 [设置 Pages 发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 常见问题

- **资料不够。** 告诉 AI 哪些暂时不想写，能用一段文字就先用文字。暂用参考内容时会保留「参考案例 · 请替换」，上线前决定替换、隐藏或保留并标注。
- **预览打不开。** 让 AI 检查本地服务是否仍运行，再发最新地址。如果点开的是 `file://`，改用 HTTP 预览。
- **图片在本机能看到，发布后找不到。** 让 AI 核对素材是否在上传清单内、文件名大小写是否一致、链接是否适用于仓库子路径。
- **换了工具或关了聊天。** 用同一个项目文件夹重新打开，发「读取本地进度，接着做」。进度保存在该文件夹的 `.portfolio/` 内。
- **首页角色在某台设备上不动。** 让 AI 先检查浏览器、视频加载以及系统是否开启了减少动态效果。需要静态图时可以选 B，请 AI 重新预览。

## 隐私

简历、参考照片、原始素材和进度留在本地。公开联系方式前，确认你愿意公开哪种方式，并换成自己的联系方式或二维码。未配置联系方式时，页面会提示暂无公开联系方式。

**`.gitignore` 只影响 Git 对未跟踪文件的处理，无法阻止手动上传，也不会自动移除已跟踪的文件。** 上传前一定再看实际文件清单。
